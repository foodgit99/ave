How the Autonomous Venture Engine works, end to end

As built in v0.1 "Reshape": one operator with an edge, eight Hyperagent agents, one Supabase project that is both shared memory and rules-based guardrail, and ventures that live entirely in the owner's own accounts. Every box below exists in the repo.

Agents coordinate only through these tables — they never talk to each other. Every hand-off is a JSON packet validated against protocol/*.schema.json (OpportunityPacket → VentureProposal → ExperimentSpec/Result → BuildSpec → DistributionPlan → DecisionRecord → OwnerReport). ledger and decisions are immutable.

Guardrails · Postgres triggers, no LLM in the loop

  • Spend status an agent writes is ignored — the trigger decides auto_approved / pending_owner / rejected
  • Expense needs an approved request with headroom; revenue counts only when verified + external_ref
  • Approve, policy, capital, kill switch: auth.uid() = owner only
  • Launch / kill / scale need an approved approvals row; max active ventures enforced
  • No discovery until owner_edge is complete
  • Launch needs owner-controlled storefront/payment + repo/hosting in venture_assets
  • Solution shape must be in the wedge; dogfood: $100 cap, stages $40/$20/$40
  • Custody / investment language raises; only the owner publishes a ledger
  • 47 / 47 tests green against embedded Postgres
agents read state · file requests · write packets, decisions, runs
